# Phase 4E.2A — Native invoice foundation

Scope: private, single order-linked USD drafts only. Based on the approved architecture at 4be5ebbc9440eabe47d4b391ccfd7c0b6ddad636. Production baseline c1db97f9798cdd0e9291fb943d5a1a697c2b9f48. All existing MCP tools and commerce handlers are unchanged. No live schema/overlay inspection was available during coding; tracked source and migration requirements were reviewed; independent read-only live schema and overlay verification is mandatory before any release or live migration. This branch is not a deployable overlay package.

New flags INVOICES_ENABLED=false and INVOICES_DRAFT_WRITES_ENABLED=false by default; commerce workspaces must also be enabled. Native UI shares domain service; no issue/void, standalone invoice, arbitrary price, tax, number reservation, delivery, email or payment action exists. Ledger records native actions (invoice.draft.create/update/discard), no MCP adapter or second audit event until 4E.3. Due-date no-op rejected. Discard terminal with one lifetime invoice/order. Native browser confirms using validated string "1" checkbox converted to true; future MCP adapter must require literal JSON true before calling typed service. No public invoice route. Existing workspace theme and shell reused. Draft detail derives payment state; not a receipt. No financial analytics totals changed. Future issue/void states are modeled but not reachable via native writes.

New migration adds three tables with restrictive foreign keys and unique order, UUID, position, actor/request constraints; MySQL checks enforce money, line and document lifecycle; SQLite exercises domain validation and FK constraints. Financial history deliberately preserved on code rollback; migration down throws. No sequence table before issuance approval. Never run the migration on production based on this branch alone.

Tests are synthetic only. NativeInvoiceFoundationTest and InvoiceMoneyTest cover flags, permissions, native route flow, snapshot, money, eligibility, strict native confirmation, versions, replay, discard, source transition, payment derivation and injected audit failure. Run both with disposable SQLite and MySQL; full existing CI and independent MySQL concurrent service/OAuth acceptance remain later gates. PHP/Blade syntax, test outcomes and browser rendering must be independently verified; branch creation is not proof of test pass. No production service, database, file, notification, invoice, OAuth or payment change authorized.
