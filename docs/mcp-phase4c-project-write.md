Stacked on Phase 4C.1; expected 38 tools (25 READ, 13 WRITE), or 25 when WRITE disabled. Four tools require mcp.read + mcp.write, current active super-admin, global WRITE switch, strict JSON scalar types, explicit boolean confirm=true, UUID request_id and opaque expected_version. Never infer confirmation from user silence. Review the exact target and payload before setting confirm=true; comments notify the other participant. No publication, payment, refund, contract acceptance, delivery approval, license or secure-note operation.

Use tracking_get.version for tasks/comments and milestones_list.version for contract milestone creation. Existing 34 tool names/input schemas stay unchanged; those two READ responses add a backward-compatible field. Version HMAC covers current parent, inquiry, payments, tasks and last message ID or contract and milestones. Read versions are optimistic snapshots; concurrent changes can cause stale rejection. Writer acquires actor and domain locks, validates verified live paid order or client-owned draft and rechecks state. Seller-only tasks honor native review/accepted freeze and 20-task cap. Contract milestones freeze after offer, maximum 20, no allocation exceeding budget. Plain comments require open inquiry and reject HTML, URL/embeds and attachments. Native in-app notification and configured email outbox enqueue are transactionally included; no direct email or gateway call. Audit records use native event plus linked MCP-specific event.

One additive migration creates mcp_project_operations with unique actor/request ID. Ledger stores HMAC payload digest and safe result, not message/description text. Exact replay returns original result with replayed=true after current authorization checks, differing payload fails; stale versions reject new requests. Ledger and domain/audit/notification writes commit together or roll back. Retain ledger and audit evidence; do not purge without separate retention decision. Native controllers remain unchanged; service mirrors native rules and uses existing model/notification/audit primitives. Actual concurrent MySQL stress and OAuth overlay acceptance are separate gates, not proven by sequential tests.

Staging utility composes the existing Phase 3, 4B and 4C READ patches from exact pinned Phase 3 controller, adds four names in dispatch and both WRITE lists; separate staging output only.
