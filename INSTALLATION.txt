BAMBODIA INSTALLATION (v0.0.1)

RELEASE STATUS
Source and initial QA are under development. Use a test domain and a fresh database first. Do not replace a production website without backups and independent acceptance.

REQUIREMENTS
PHP 8.3+, MySQL/MariaDB with PDO MySQL, required Laravel PHP extensions, HTTPS, writable storage/ and bootstrap/cache/, and an aaPanel/cPanel/Nginx/Apache host configured to serve public/ as the document root.

ONE-CLICK BROWSER SETUP (PACKAGED RELEASE ONLY)
1. Upload the complete build artifact, including vendor/ and public/build/.
2. Extract into a new empty installation directory. Do not expose the project root publicly.
3. Configure the website's document root to the project's public/ directory. On Apache ensure mod_rewrite and public/.htaccess work. On Nginx route requests through public/index.php.
4. Create an EMPTY MySQL database and a database user with the rights needed to create the application's tables.
5. Visit https://your-domain/installer and check the Requirements page.
6. In hosting file manager, open storage/app/installer-access.txt and read the installation access code. Enter that code into the wizard. This key is a setup authorization code, NOT a marketplace product purchase license.
7. Enter MySQL connection values, verify application URL, and create the initial super administrator. Select Install.
8. Installer writes a private .env, applies migrations, creates the super administrator and locks installation. Sign in via /login.

SECURITY AND LIMITATIONS
Do not set APP_DEBUG=true on production. Never upload a .env with real credentials to GitHub. Do not point the document root to the project root. The installer refuses existing tables and does not delete or replace a preexisting .env. The setup access code is destroyed after installation and the installer is disabled by installed.lock.

SMTP must be configured before password reset mail can be delivered. Publishing products and listing prices does NOT enable payment processing, refunds, license delivery or escrow. Those workflows remain disabled until external provider and security verification.

Rollback requires a prior full website and database backup. The current installer is for NEW empty databases and is not an upgrade/migration wizard. Do not reuse it to update a live Bambodia installation.


POST-INSTALL SCHEDULER
To apply the configured 90-day audit retention and other future scheduled jobs, configure a hosting cron job after installing Bambodia:
  * * * * * /path/to/php /absolute/path/to/bambodia/artisan schedule:run >> /dev/null 2>&1
Use the PHP binary for your installed application and set the correct absolute project path. For hosts with a control panel, use its Cron Jobs interface. If cron is not configured, automatic audit retention will not run.

DEVELOPER AND SECURITY MODULES
/developer and /security-dashboard require a Super Admin account. Use /developer/docs for the available read-only API methods. Credentials are shown once and stored only as hashes; scope, expiration and revocation are enforced on every request. The security audit stores no raw IP addresses or request body contents.


PRODUCT AND MEDIA ACCEPTANCE
Create a license definition in /dashboard/license-manager and activate it after human legal review. An approved Creator uploads genuine JPEG, PNG or WebP previews in /studio/media-library, with rights-holder data. An administrator reviews those images in /dashboard/media-library. A Creator can then submit a Product with the active license and approved owned image in /studio/products. An administrator approves or rejects in /dashboard/product-manager.

Private media files must remain in storage/app/private, never in a public symlink. The public document root must remain the Laravel public/ directory. Site operators must independently verify host limits for PHP upload sizes, file permissions, HTTPS and PHP modules.

Preview images are separate from original downloadable ZIP/PPTX/PDF files. The source-file vault and version-specific manual download entitlements are implemented but have not been accepted on live shared hosting. Automated paid purchase delivery, order payment verification, refunds, tax invoices, and financial transaction processing remain disabled. The release is not approved for customer financial transactions.
 
PRIVATE DIGITAL FILE VAULT
PHP zip extension is required. Creators with a published and rights-reviewed digital product may upload original ZIP, PPTX or PDF files in /studio/products/{product}/releases. Each version is immutable, stored in storage/app/private, and limited to 25 MiB. PHP upload_max_filesize and post_max_size must be configured high enough for intended uploads, and the host must have sufficient private disk space. ZIP archives are checked for unsafe paths, symlinks, entry-count limits and unsafe expansion; no archives are extracted during the upload.
 
Administrators inspect an original via an authenticated, logged download and explicitly approve, reject, or disable the release at /dashboard/file-vault. These checks are NOT malware scanning; product operators need independent malware/content screening and license rights verification before real customer distribution.
 
The Super Admin can grant a specific approved version to an existing Customer, Subscriber or Freelancer by eight-digit public ID at /dashboard/entitlements, providing a reason and expiration window and confirming that no payment is being claimed. Grants, re-grants, and revocations retain individual history events.
 
The recipient's /account/downloads page permits only identity-bound, unexpired, unrecalled entitlements. Every download revalidates product publication, release approval, entitlement status, file size, and SHA-256 digest. No public direct file URL is generated.
 
After installing on aaPanel/cPanel, run independent upload, review, download, expiry, revocation, ZIP and PPTX/PDF acceptance tests before any customer release. Production deployments and actual malware scanning are not yet accepted.


NEW WORKFLOW HOSTING ACCEPTANCE
Test approved job visibility and freelancer applications, role authorization of private proposals, closed-job behavior, category filtering, and private inquiry access from both participant accounts. Verify notification inbox ownership and read state; in-app messages do not constitute verified email delivery. Confirm the admin listings and categories use exactly ten items per table page and functional Configure actions.

Do not activate paid checkout, freelancer escrow or transactions. This one-click installer only accepts a fresh empty database, not upgrades to an existing installation. Use a fully backed-up staging installation for this verification.


APPEARANCE AND SETTINGS TEST
On a fresh installation visit /dashboard/appearance and /dashboard/system-settings as Super Admin or Admin. Change the English homepage headline and confirm it appears on the public homepage. Disable and re-enable the homepage search and category quick links to verify real visibility changes. Change the default guest theme and locale and test with an independent browser session. Configure a public support email only if the site's verified operator owns the address; this setting is a public mailto contact, not an SMTP credential or an outgoing email integration.

Do not use installer setup on an existing production database. Back up file storage, database and the full environment configuration before manual upgrade testing.
